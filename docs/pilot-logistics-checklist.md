# Pilot Logistics Checklist

## Purpose

This is the on-ramp for [MODERNIZATION-PLAN.md](MODERNIZATION-PLAN.md) Phase 3, item 4: **piloting the [core interview loop](core-interview-loop.md) with experienced interviewers and revising questions that create uneven interpretation.** That step cannot be done from the repository alone — it requires real interviews with real interviewers. This checklist is not the pilot itself; it's what a human owner needs to actually run one and bring back something actionable.

## Before The Pilot

- [ ] **Pick one role and one [role-loop-preset](role-loop-presets.md)** to pilot first. Don't pilot the whole 34-card bank at once — pick the preset closest to your next real opening.
- [ ] **Recruit 2-3 experienced interviewers** who haven't used this toolkit before. Deliberately include at least one skeptic — someone who'll push back on a card that doesn't work, not just people inclined to like the project.
- [ ] **Recruit 2-4 pilot candidates.** Real candidates in an active loop are ideal (best ecological validity); internal volunteers doing a mock interview are an acceptable fallback if timing doesn't allow real candidates yet — note which you used, since it affects how much weight to put on the results.
- [ ] **Brief interviewers on the toolkit before the pilot**, not during it: [structured-interview-guide.md](structured-interview-guide.md), [scoring-rubric.md](scoring-rubric.md), [evidence-and-pressure-standard.md](evidence-and-pressure-standard.md), and the [scorecard template](interview-scorecard-template.md). Confusion during the pilot about how the *tools* work will contaminate the signal about how the *questions* work.
- [ ] **Confirm every interviewer has the scorecard template ready** (a copy per candidate per round) before the first interview, not scrambling for it mid-interview.

## During The Pilot

- [ ] **Run the loop exactly as documented** — same rounds, same selected questions per candidate, real scorecards filled live or immediately after. Don't let interviewers improvise a "better" version mid-pilot; that's exactly the data you need the pilot to surface, but it needs to happen as feedback afterward, not as silent deviation during.
- [ ] **Time each round.** Note whether 3-4 questions actually fit in 45-60 minutes as designed, or whether the real pace ran long or left dead air.
- [ ] **Capture interviewer friction in the moment** — a card that felt awkward to ask, a follow-up probe that didn't land, a warning sign that didn't show up the way the card predicted. A quick note during or immediately after beats a reconstructed memory in the debrief.

## After Each Pilot Interview

- [ ] **Collect the filled scorecards** before the debrief conversation — this preserves the independent-scoring discipline the whole toolkit is built around.
- [ ] **Have each interviewer separately note**: which question(s) they'd keep, cut, or rewrite, and why — evidence-based ("the strong-evidence bullet didn't match what a good answer actually looked like"), not vibes-based ("didn't love it").

## Comparing Interviewer Scores (The Actual Point Of The Pilot)

- [ ] **Compare scores for the same competency across interviewers**, where more than one interviewer covered the same round or overlapping ground (deliberately arrange at least one round of overlap during the pilot specifically to make this comparison possible).
- [ ] **Where scores diverge by more than one point** on the same competency for the same candidate, dig into *why* — per [scoring-rubric.md](scoring-rubric.md)'s Calibration section, this is a signal about the question or the anchor, not (necessarily) about the candidate.
- [ ] **Distinguish three different failure modes**, since the fix is different for each:
  - **The question itself is ambiguous** — different interviewers heard different things from the same answer. Fix: rewrite the question or its Strong Evidence / Warning Signs sections.
  - **The scoring anchors are ambiguous** — interviewers agreed on what happened but scored it differently. Fix: sharpen [scoring-rubric.md](scoring-rubric.md)'s anchors, possibly add a worked example.
  - **The interviewers weren't calibrated** — one was simply harsher or softer across the board, independent of the question. Fix: more shadow-scoring practice per the Calibration section, not a change to the question bank.

## Closing The Loop

- [ ] **For any card that created real, repeated ambiguity**, edit the card directly — its Strong Evidence, Warning Signs, or Scoring Anchors sections — rather than just noting the problem somewhere and moving on.
- [ ] **Update [question-bank-triage.md](question-bank-triage.md)** with a pilot note if a card's disposition changes as a result (e.g., a card that seemed strong on paper turns out to need real rework).
- [ ] **Update this checklist** if the pilot surfaces a logistics problem this document didn't anticipate — that's exactly the kind of feedback loop the pilot exists to produce.
- [ ] **Decide whether to pilot a second preset** or consider Phase 3, item 4 sufficiently addressed for now. One pilot on one preset is a reasonable first pass; it doesn't need to cover all four presets before the loop is considered usable.

## What "Done" Looks Like

Per [MODERNIZATION-PLAN.md](MODERNIZATION-PLAN.md)'s Definition of Done: a new interviewer can select a role-appropriate loop, ask each question consistently, record evidence, score it against shared anchors, and understand why a question belongs in the process — without inferring the philosophy from scratch. A successful pilot is evidence that this is actually true for someone who wasn't involved in building the toolkit, not just true for the people who wrote it.
